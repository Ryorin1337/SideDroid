## 尚未验证

- **手机端全部运行行为：** APK 只通过了编译和 lint，没有在任何设备或模拟器上启动过。解码、触控上报、旋转、配对都未跑过。
- **虚拟显示驱动：** 需要管理员权限和人工确认，尚未安装。不开测试模式能否装上、`RELOAD_DRIVER` 能否让新分辨率生效，都要实测。
- **MSI 的实际安装和卸载：** 只检查过内容，没有运行。
- **触控注入：** 只验证了能创建触控设备，为了不干扰你的桌面，没有实际注入。
- **USB：** `adb reverse` 流程没有接过真机。
- **真实 Wi-Fi：** 丢包和限速是模拟的，真实无线网络的表现未知。
- **Media Foundation 编码：** 这台电脑一直走 NVENC，Intel 和 AMD 的路径没有跑过。
- **混合显卡跨 GPU 拷贝：** 这台电脑当前的屏幕就在 NVIDIA 上，没有触发。虚拟屏接上后可能会用到。

## 与原计划不同的地方

| 计划 | 实际 | 原因 |
|---|---|---|
| 后台高权限服务写配置 | 不做服务，安装时给配置目录授权 | VDD 的管道本身就对所有本地用户开放，可以直接发 `RELOAD_DRIVER`。少一个 SYSTEM 服务，攻击面更小 |
| TLS + AES-GCM | Monocypher（X25519 + XChaCha20-Poly1305） | Android NDK 没有 TLS，同一份代码可以跑在两端。代价是定制握手没有经过审计 |
| 二维码配对 | **只做了配对码** | 二维码还需要相机权限和扫码组件。配对码已能完成配对 |
| 控制台延迟码率小图 | 数字卡片 | 更简洁，小图可以以后再加 |
| 一个 Gradle 工程 | 两个独立工程共用一个源码目录 | Windows 没有 Android SDK，WSL 不构建桌面端，这样互不影响 |

## 已知限制

- **管理员窗口：** 触控无法操作管理员权限的窗口和 UAC 界面。
- **鼠标形状：** 需要反色的光标（如部分文本光标）显示为纯白。
- **VDD 的管道对所有本地程序开放：** 这是上游驱动的设计。任何本地程序都能让虚拟屏重载或改变数量，但拿不到画面。
- **配置目录权限：** 安装后所有本地用户都能修改 `C:\VirtualDisplayDriver`。
- **驱动发布者：** 显示为 SignPath Foundation，这是该驱动上游的签名方。
- **Material 3 Expressive：** 依赖 alpha 版 API（CMP `1.12.0-alpha03`，androidx `1.5.0-alpha22`），升级时可能需要改代码。
- **Android 版 APK：** 目前用调试密钥签名，只适合测试，正式发布前要换成自己的密钥。
- **界面语言：** 只有中文。

## 技术验证（M0）结论

1. **驱动签名：** VDD 25.7.23 的 `.cat` 和 `.dll` 都是 SignPath Foundation 的 Authenticode 签名（GlobalSign），不是微软 attestation 签名，也没有内核代码签名策略的信任链（`signtool /kp` 失败）。它是用户态驱动，因此理论上可行，上游的静默安装脚本也只是把证书加入受信任发布者。SideDroid 不导入证书，由 Windows 弹出确认。**是否能在 Secure Boot 下装上要在验收时确认。**
2. **控制接口：** 驱动有 `\\.\pipe\MTTVirtualDisplayPipe`，支持 `RELOAD_DRIVER`、`SETDISPLAYCOUNT` 等命令。上述结论来自上游源码和发布版二进制中的字符串，没有实际调用过。
3. **虚拟屏识别：** 监视器硬件 ID 含 `MTT1337`。本机的 Virtual Desktop（VR 串流）和 ToDesk 虚拟设备不会匹配。
4. **MD3E 桌面端：** Compose Multiplatform 1.12.2 配 Material3 `1.12.0-alpha03` 可以编译和渲染，并非只限 Android。
5. **混合显卡：** 开发机当前屏幕由 NVIDIA 驱动，NVENC 可以零拷贝。跨 GPU 路径已实现但未触发。
