# Android 解码与显示

解码桥接实现在 [android/app/src/main/cpp/bridge.cpp](../android/app/src/main/cpp/bridge.cpp)，编码帧队列在 [decoder_queue.h](../android/app/src/main/cpp/decoder_queue.h)。两端传输约定见 [协议](protocol.md)，Windows 的虚拟屏和桌面布局见 [显示布局](displays.md)。

## 输入与参考链

网络线程只把完整编码帧复制进有上限的队列，独立输入线程等待 MediaCodec 缓冲，避免解码等待阻塞 TCP 或 UDP 收包。队列最多保留 3 帧，待提交帧的年龄预算约为两个帧周期，限制在 16–50ms：

```text
maxAgeUs = clamp(2000000 / max(fps, 1), 16000, 50000)
```

入队、出队和提交前都会检查是否过期，等待输入缓冲的时间不超过剩余预算，也不超过 20ms；这不是每帧固定等待 20ms。积压超限后清除整条待解码参考链，从新的关键帧恢复，不单独跳过仍被后续 P 帧依赖的编码帧。恢复等待期间会重试请求关键帧。

输入线程负责创建、刷新和销毁 codec。Surface、配置或参考链变化时切换代际，旧代际的工作不再提交显示；刷新或销毁前先停止并等待输出线程结束。若冷启动或刷新太慢，使手里的关键帧过期，下一次恢复保留尚未领取输入缓冲的空 codec，避免每个新关键帧都把预算花在重复初始化上。已经领取的输入缓冲即使未提交，也必须通过刷新回收。

## 低延迟配置与输出

解码器按编码类型创建，请求实时优先级、Android 标准低延迟选项及厂商扩展。厂商选项被拒绝时，先保留标准低延迟选项重试，再回退基础配置。是否实际支持这些选项取决于设备和解码器，不能只凭配置请求判断延迟。

输出线程取走所有当下可用的输出，丢弃已经解码但过时的显示缓冲，只把最新可用输出交给 Surface。这些帧已经参与解码，不会破坏后续帧的参考链；显示合成和屏幕扫描仍在后面发生。

本地队列过载或提交失败通过 `Client::reportDecoderDrop()` 进入现有 `Stats.framesDropped` 反馈，一次参考链丢弃或提交失败恢复记一次，不是逐帧统计清掉的所有帧。等待关键帧期间跳过的 P 帧、输出端淘汰的旧显示缓冲、Surface 和配置切换不算这种过载反馈。`Stats.decodeUs` 的口径见 [协议](protocol.md)，和 RTT、画面延迟的区别见 [延迟诊断](troubleshooting.md)。

## 画面适配

画面和屏幕比例不同时怎么显示。这只和客户端有关，不影响采集和编码，但设置按设备保存在 Host（`settings.ini` 的 `fill`），所以控制台、托盘和手机显示的是同一个值。

| 值 | 名称 | 手机端的做法 |
|---|---|---|
| 0 | 适应 | 显示完整画面，留黑边 |
| 1 | 填充 | 放大到没有黑边，超出屏幕的部分裁掉 |
| 2 | 拉伸 | 铺满屏幕，比例会变 |
| 3 | 平铺 | 按原始大小重复；画面比屏幕大时先缩小到放得下 |

前三种只改变 `SurfaceView` 的大小和位置，触摸坐标按视图换算，不需要特殊处理。平铺要把一路解码输出画多次，所以改用 `SurfaceTexture` 和 OpenGL（`TiledVideoView`），只有这个模式走这条路径。平铺时每根手指属于按下时所在的那份画面，滑到相邻画面时停在边缘，不会跳回另一侧。

## 测试范围

[decoder_queue_tests.cpp](../android/app/src/test/cpp/decoder_queue_tests.cpp) 不依赖 Android 运行时，检查队列顺序、帧数和年龄上限、参考链恢复、配置失效以及过载计数。APK 编译验证 JNI 和 NDK 接口能否构建，但队列测试覆盖不到厂商 MediaCodec、Surface 生命周期和真实呈现时间，这些仍需真机验证。
